# Online Retail: загрузка, качество данных, аналитика

Датасет: [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail),
541 909 строк продаж британского онлайн-магазина за 01.12.2010 - 09.12.2011.

## Запуск

```bash
./gradlew run --args="data.csv out"          # потоков = по числу ядер
./gradlew run --args="data.csv out 4"        # 4 потока на запросах
./gradlew test                               # тесты
```

## Что происходит

| Шаг | Что делает | Выход |
|---|---|---|
| 1. Ingest | CSV -> колоночный слой, отбраковка только технически битых строк | `out/raw.parquet`, `out/rejected_ingest.csv` |
| 2. Data Quality | 12 правил, нормализация справочника товаров, разметка возвратов | `out/prepared.parquet`, `out/rejected.csv`, `out/dq_report.csv` |
| 3. Queries | 3 запроса, в один поток и параллельно по row group | в памяти |
| 4. Save | выгрузка результатов | `out/top_products.csv`, `out/customer_metrics.csv`, `out/monthly_revenue.csv` |

Архитектура и UML: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Решения по данным

Деньги хранятся и суммируются целым числом в масштабе 10^4: в `UnitPrice`
максимум 3 знака после запятой, так суммы точные и не зависят от порядка
слагаемых. Это важно для параллельной агрегации.

**Возвраты.** Номер счёта-отмены (`C536379`) не ссылается на исходный заказ:
пересечение C-номеров с номерами обычных счетов нулевое. Поэтому возврат это
самостоятельный документ. Строка помечается `LineFlow = RETURN`, из выгрузки
не удаляется. В метриках считаются обе величины: gross (только продажи) и
netto (с вычетом возвратов).

**Служебные позиции.** `POST`, `DOT`, `C2` - доставка, `M`, `D`, `B` - ручные
корректировки, `BANK CHARGES`, `AMAZONFEE` - сборы, `gift_0001_*` - сертификаты,
`S` - образцы. Они попадают в деньги клиента (он их реально заплатил), но
исключены из топа товаров: иначе рейтинг возглавила бы доставка.

**Справочник товаров.** У 647 кодов из 4070 несколько разных `Description`.
Берётся самое частое непустое описание на код, при равенстве - лексикографически
меньшее, чтобы прогон был воспроизводимым.

**Заказы без клиента.** 135 080 строк без `CustomerID` остаются в
подготовленном слое (предупреждение `customer.missing`), но в клиентских
метриках не участвуют: привязать их к клиенту нельзя.

## Замечание по месяцам

В `monthly_revenue.csv` у декабря 2011 доля возвратов 32%: месяц обрезан 9-м
числом, а возвраты приходят с задержкой относительно продаж. Это артефакт
границы датасета, а не поведение клиентов.
